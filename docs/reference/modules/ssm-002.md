# `ssm-002` — ssm:SendCommand

|  |  |
|---|---|
| ID | `ssm-002` |
| Category | existing-passrole |
| Services | iam, ssm |
| Author | Seth Art |
| Aliases | `ssm-sendcommand`, `exploit/ssm_sendcommand` |
| pathfinding.cloud | https://pathfinding.cloud/paths/ssm-002 |

Use ssm:SendCommand to execute commands on a running EC2 instance that has a privileged IAM role attached via an instance profile. The selected payload determines what action to take with the instance role's credentials or IAM permissions. The instance must have the SSM agent installed and the AmazonSSMManagedInstanceCore policy (or equivalent) attached to its role.

## Required permissions

- `ssm:SendCommand` — Target EC2 instance must be in the Resource section of the policy

## Additional permissions

- `ec2:DescribeInstances` — Discover available EC2 instances with privileged instance profiles
- `ssm:DescribeInstanceInformation` — Identify instances with SSM agent online and ready for commands
- `ssm:ListCommandInvocations` — Retrieve command output from the executed payload
- `ssm:GetCommandInvocation` — Alternative method to retrieve command output

## Prerequisites

**Admin:**
- EC2 instance must exist and be in running state
- EC2 instance must have the SSM agent installed (Amazon Linux 2/2023 and Ubuntu include it by default)
- EC2 instance must have an instance profile attached to an IAM role
- IAM role must have the AmazonSSMManagedInstanceCore policy (or equivalent SSM permissions)
- Target EC2 instance must have a role with the permissions needed by the selected payload

**Lateral:**
- EC2 instance must exist and be in running state
- EC2 instance must have the SSM agent installed
- EC2 instance must have an instance profile attached to an IAM role
- IAM role must have the AmazonSSMManagedInstanceCore policy (or equivalent SSM permissions)

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `INSTANCE_ID` | yes | — | Target EC2 instance ID (must have SSM agent running and a privileged instance profile) |
| `PAYLOAD` | yes | — | Payload to execute on the instance (run 'payloads list' to see available options) |
| `REGION` | no | `us-east-1` | AWS region where the target instance runs |

## Compatible payloads

- `backdoor/attach-policy` — Attach a policy to an IAM user or role using the instance role's IAM permissions
- `backdoor/create-access-key` — Create access keys for an IAM user using the instance role's IAM permissions
- `backdoor/create-role` — Create an IAM role with administrator privileges using the instance role's IAM permissions
- `backdoor/create-user` — Create an IAM user with administrator privileges using the instance role's IAM permissions
- `backdoor/update-role-trust` — Append a trust policy statement to an IAM role using the instance role's IAM permissions
- `exfil/https` — Exfiltrate instance role credentials to an attacker-controlled HTTPS endpoint via SSM command
- `exfil/s3` — Exfiltrate instance role credentials to an attacker-controlled S3 bucket via SSM command
- `revshell/tls` — Establish a TLS-encrypted reverse shell via SSM command
- `shell/interactive` — Open a live interactive shell via the SSM session (no reverse connection required)
