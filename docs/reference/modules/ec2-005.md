# `ec2-005` — ec2:CreateLaunchTemplateVersion + ec2:ModifyLaunchTemplate

|  |  |
|---|---|
| ID | `ec2-005` |
| Category | existing-passrole |
| Services | iam, ec2 |
| Author | Seth Art |
| Aliases | `ec2-launch-template-version`, `exploit/ec2_launch_template_version` |
| pathfinding.cloud | https://pathfinding.cloud/paths/ec2-005 |

Create a new version of an existing EC2 launch template, embedding a malicious user-data script and explicitly setting a privileged IAM instance profile. Set the new version as the default. Trigger an Auto Scaling Group to launch an instance — the ASG service role holds iam:PassRole, so the attacker avoids the PassRole requirement — and let the user-data script attach AdministratorAccess to the starting principal.

## Required permissions

- `ec2:CreateLaunchTemplateVersion` — Must be able to create a new version of the target launch template
- `ec2:ModifyLaunchTemplate` — Must be able to modify the target launch template to set the new version as default
- `autoscaling:SetDesiredCapacity` — Must be able to set ASG desired capacity to trigger an instance launch

## Additional permissions

- `ec2:DescribeLaunchTemplates` — Helpful for discovering launch templates
- `ec2:DescribeLaunchTemplateVersions` — Useful for viewing current default version configuration
- `autoscaling:DescribeAutoScalingGroups` — Used to discover ASGs using the target launch template
- `iam:ListAttachedUserPolicies` — Useful for verifying privilege escalation success

## Prerequisites

**Admin:**
- An existing EC2 launch template must exist that the starting principal can create new versions of
- An Auto Scaling Group must use the target launch template as its launch template
- A privileged IAM instance profile must exist that the ASG service role can pass
- The privileged instance profile role must have permissions to call iam:AttachUserPolicy

**Lateral:**
- An existing EC2 launch template must exist with elevated IAM instance profile accessible via an ASG

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `LAUNCH_TEMPLATE_NAME` | yes | — | Name of the existing target launch template |
| `ASG_NAME` | yes | — | Name of the Auto Scaling Group to trigger for instance launch (avoids iam:PassRole requirement) [auto] |
| `INSTANCE_PROFILE` | yes | — | ARN or name of the privileged IAM instance profile to embed in the new template version [auto] |
| `PAYLOAD` | yes | — | Payload type (backdoor/attach-policy, revshell/tls, exfil/https) |
| `TARGET_ARN` | no | — | IAM user or role ARN/name to receive elevated permissions (used by backdoor/attach-policy payload) |
| `REGION` | no | `us-east-1` | AWS region |
| `WAIT_FOR_POLICY` | no | `true` | Poll for IAM policy attachment after instance launch (up to 5 minutes, from demo_attack.sh) |
| `CLEANUP` | no | `false` | Restore original default version after execution |

## Compatible payloads

- `backdoor/attach-policy` — Attach AdministratorAccess policy to an IAM user or role via EC2 user-data
- `backdoor/create-access-key` — Create access keys for an existing IAM user via EC2 user-data
- `backdoor/create-role` — Create an IAM role with administrator privileges and custom trust policy via EC2 user-data
- `backdoor/create-user` — Create an IAM user with administrator privileges and optional console/programmatic access via EC2 user-data
- `backdoor/update-role-trust` — Append a trust policy statement to an existing IAM role via EC2 user-data
- `exfil/https` — Exfiltrate instance role credentials to an attacker-controlled HTTPS endpoint via EC2 user-data
- `exfil/s3` — Exfiltrate EC2 instance role credentials to an attacker-controlled S3 bucket via user-data
- `revshell/tls` — Establish a TLS-encrypted reverse shell via EC2 user-data
