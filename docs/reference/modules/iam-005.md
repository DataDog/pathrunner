# `iam-005` — iam:PutRolePolicy

|  |  |
|---|---|
| ID | `iam-005` |
| Category | self-escalation |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-putrolepolicy`, `exploit/iam_putrolepolicy` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-005 |

A principal with iam:PutRolePolicy can attach inline policies to any role they have this permission on. This is frequently exploited for self-escalation by granting the caller's own role full administrative access.

## Required permissions

- `iam:PutRolePolicy` — Target role must be in Resource section; for self-escalation, must have permission on own role

## Additional permissions

- `iam:GetRolePolicy` — View existing inline policies
- `iam:ListRolePolicies` — Discover existing inline policies on the role
- `sts:AssumeRole` — Required when starting as a user to assume the target role

## Prerequisites

**Admin:**
- Role must have iam:PutRolePolicy permission on itself
- If starting as a user, must be able to assume the target role

**Lateral:**
- Role must have iam:PutRolePolicy permission on itself
- If starting as a user, must be able to assume the target role

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `ROLE_ARN` | no | — | ARN of the role to escalate (auto-detected from caller if caller is a role; required when caller is a user) |
| `POLICY_NAME` | no | `pathrunner-admin` | Name for the inline policy to add |
| `REGION` | no | `us-east-1` | AWS region for IAM operations |
| `VERIFY` | no | `true` | Verify escalation by calling iam:ListUsers after (true/false) |
