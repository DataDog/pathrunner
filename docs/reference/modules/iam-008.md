# `iam-008` — iam:AttachUserPolicy

|  |  |
|---|---|
| ID | `iam-008` |
| Category | self-escalation |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-attachuserpolicy`, `exploit/iam_attachuserpolicy` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-008 |

A principal with iam:AttachUserPolicy can attach managed policies to any user they have this permission on. This is frequently exploited for self-escalation by attaching the AdministratorAccess managed policy to the caller's own user.

## Required permissions

- `iam:AttachUserPolicy` — Target user must be in Resource section; for self-escalation, must have permission on own user

## Prerequisites

**Admin:**
- A managed IAM policy with elevated privileges must exist in the account
- Principal must be a user (not a role)

**Lateral:**
- A managed IAM policy with elevated privileges must exist in the account
- Principal must be a user (not a role)

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `POLICY_ARN` | no | `arn:aws:iam::aws:policy/AdministratorAccess` | ARN of the managed policy to attach (defaults to AdministratorAccess) |
| `REGION` | no | `us-east-1` | AWS region for IAM operations |
| `VERIFY` | no | `true` | Verify escalation by calling iam:ListUsers after (true/false) |
