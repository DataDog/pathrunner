# `ssm-003` — iam:PassRole + ssm:CreateDocument + ssm:StartAutomationExecution

|  |  |
|---|---|
| ID | `ssm-003` |
| Category | new-passrole |
| Services | iam, ssm |
| Author | Seth Art |
| Aliases | `ssm-passrole-automation`, `exploit/ssm_passrole_automation` |
| pathfinding.cloud | https://pathfinding.cloud/paths/ssm-003 |

Create a custom SSM Automation document with a Python aws:executeScript step, then start an execution that passes a privileged IAM role as AutomationAssumeRole. SSM runs the embedded Python in AWS-managed serverless compute under the admin role's credentials — no EC2 instance, Lambda function, or container is required. The selected payload determines what IAM action to perform.

## Required permissions

- `iam:PassRole` — Must be able to pass the target admin IAM role to the SSM Automation service as AutomationAssumeRole
- `ssm:CreateDocument` — No resource constraints required
- `ssm:StartAutomationExecution` — No resource constraints required

## Additional permissions

- `ssm:GetAutomationExecution` — Poll execution status to confirm the Python script ran successfully
- `ssm:DescribeAutomationExecutions` — List and monitor automation executions
- `ssm:ListDocuments` — Discover existing SSM documents
- `ssm:DescribeDocument` — Inspect document content before execution

## Prerequisites

**Admin:**
- A role must exist that trusts ssm.amazonaws.com to assume it
- The role must have the permissions needed by the selected payload (e.g., iam:AttachUserPolicy for backdoor/attach-policy)

**Lateral:**
- A role must exist that trusts ssm.amazonaws.com and has elevated permissions

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `ROLE_ARN` | yes | — | ARN of the IAM role to pass as AutomationAssumeRole (must trust ssm.amazonaws.com and have the permissions needed by the selected payload) |
| `PAYLOAD` | yes | — | Payload to execute via SSM Automation Python step (run 'payloads list' to see available options) |
| `DOCUMENT_NAME` | no | — | Name for the SSM Automation document to create |
| `REGION` | no | `us-east-1` | AWS region for SSM Automation execution |
| `CLEANUP` | no | `false` | Delete the SSM Automation document after execution. Note: the starting user typically lacks ssm:DeleteDocument — use 'workspace cleanup' with admin credentials instead. |

## Compatible payloads

- `backdoor/attach-policy` — Attach a policy to an IAM user or role via SSM Automation Python step
- `backdoor/create-access-key` — Create access keys for an IAM user via SSM Automation Python step
- `backdoor/create-role` — Create an IAM role with administrator privileges via SSM Automation Python step
- `backdoor/create-user` — Create an IAM user with administrator privileges via SSM Automation Python step
- `backdoor/update-role-trust` — Append a trust policy statement to an IAM role via SSM Automation Python step
