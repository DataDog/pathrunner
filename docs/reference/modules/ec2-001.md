# `ec2-001` — iam:PassRole + ec2:RunInstances

|  |  |
|---|---|
| ID | `ec2-001` |
| Category | new-passrole |

| Author | Seth Art |
| Aliases | `ec2-passrole`, `exploit/ec2_passrole` |
| pathfinding.cloud | https://pathfinding.cloud/paths/ec2-001 |

Launch an EC2 instance with a privileged role attached, execute code via user-data scripts

## Required permissions

- `iam:PassRole` — Target instance profile role ARN
- `ec2:RunInstances`

## Additional permissions

- `ec2:DescribeImages` — Auto-detect AMI
- `ec2:DescribeVpcs` — Auto-detect default VPC
- `ec2:DescribeSubnets` — Auto-detect subnet

## Prerequisites

**Admin:**
- IAM instance profile with desired permissions
- VPC with subnet for instance placement

**Lateral:**
- Principal with iam:PassRole and ec2:RunInstances

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `INSTANCE_PROFILE` | yes | — | Target IAM instance profile name or ARN to pass to EC2 instance |
| `PAYLOAD` | yes | — | Payload type (backdoor/attach-policy, exfil/https, revshell/tls) |
| `REGION` | no | `us-east-1` | AWS region for EC2 instance deployment |
| `AMI_ID` | no | — | AMI ID for EC2 instance (will auto-detect Amazon Linux 2023 if not specified) |
| `INSTANCE_TYPE` | no | `t3.micro` | EC2 instance type |
| `SUBNET_ID` | no | — | Subnet ID for instance placement (will use default VPC if not specified) |
| `SECURITY_GROUP_ID` | no | — | Security group ID to attach (optional) |
| `INSTANCE_NAME` | no | — | Name tag for the EC2 instance |
| `WAIT_FOR_READY` | no | `true` | Wait for instance to reach running state |
| `CLEANUP` | no | `false` | Terminate instance after execution |

## Compatible payloads

- `backdoor/attach-policy` — Attach AdministratorAccess policy to an IAM user or role via EC2 user-data
- `backdoor/create-access-key` — Create access keys for an existing IAM user via EC2 user-data
- `backdoor/create-role` — Create an IAM role with administrator privileges and custom trust policy via EC2 user-data
- `backdoor/create-user` — Create an IAM user with administrator privileges and optional console/programmatic access via EC2 user-data
- `backdoor/update-role-trust` — Append a trust policy statement to an existing IAM role via EC2 user-data
- `exfil/https` — Exfiltrate instance role credentials to an attacker-controlled HTTPS endpoint via EC2 user-data
- `exfil/s3` — Exfiltrate EC2 instance role credentials to an attacker-controlled S3 bucket via user-data
- `revshell/tls` — Establish a TLS-encrypted reverse shell via EC2 user-data
