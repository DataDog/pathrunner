# `iam-018` — iam:PutUserPolicy + iam:CreateAccessKey

|  |  |
|---|---|
| ID | `iam-018` |
| Category | principal-access |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-putuserpolicy-createaccesskey`, `exploit/iam_putuserpolicy_createaccesskey` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-018 |

Add an inline policy with admin permissions to a target user, then create access keys for that user. Unlike managed policy attachment, inline policies are embedded directly in the user object and are less visible in some security reviews.

## Required permissions

- `iam:PutUserPolicy` — Must have access to add inline policies to the target user
- `iam:CreateAccessKey` — Must have permission to create access keys for the target user

## Additional permissions

- `iam:ListUsers` — Discover available users
- `iam:ListAccessKeys` — Check existing access key count

## Prerequisites

**Admin:**
- Target user must have fewer than 2 access keys (AWS limit)

**Lateral:**
- Target user must have fewer than 2 access keys (AWS limit)

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `TARGET_USER` | yes | — | Target IAM username |
| `POLICY_NAME` | no | `pathrunner-admin` | Name for the inline policy to add |
| `REGION` | no | `us-east-1` | AWS region for IAM/STS operations |
| `AUTO_SWITCH` | no | `true` | Automatically switch to new identity after successful key creation |
