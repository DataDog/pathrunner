# `ecs-007` — iam:PassRole + ecs:StartTask + ecs:RegisterContainerInstance

|  |  |
|---|---|
| ID | `ecs-007` |
| Category | new-passrole |
| Services | iam, ecs |
| Author | Seth Art |
| Aliases | `ecs-starttask-registercontainerinstance`, `exploit/ecs_starttask_registercontainerinstance` |
| pathfinding.cloud | https://pathfinding.cloud/paths/ecs-007 |

Register an EC2 instance to an ECS cluster and start an existing task definition with overrides to pass a privileged role and execute arbitrary container commands — no ecs:RegisterTaskDefinition required

## Required permissions

- `iam:PassRole` — Must cover both the task role ARN (override) and the execution role in the existing task definition
- `ecs:RegisterContainerInstance` — Register the EC2 instance to the target cluster via direct API call using IMDS identity documents
- `ecs:StartTask` — Start tasks on container instances in the target cluster

## Additional permissions

- `ecs:ListClusters` — Discover available ECS clusters
- `ecs:ListContainerInstances` — Discover registered container instances
- `ecs:ListTaskDefinitions` — Discover existing task definitions to exploit
- `ecs:DescribeTasks` — Monitor task execution status
- `ecs:DeregisterContainerInstance` — Clean up orphaned container instance registrations
- `iam:ListRoles` — Discover roles that trust ecs-tasks.amazonaws.com

## Prerequisites

**Admin:**
- Attacker has RCE on an EC2 instance whose role has the required permissions
- An ECS cluster must exist in the account
- An existing task definition must be available
- A role must exist that trusts ecs-tasks.amazonaws.com with administrative permissions
- The EC2 instance must be registered to the cluster (this module handles the StartTask step; registration is a prerequisite)

**Lateral:**
- Attacker has RCE on an EC2 instance whose role has the required permissions
- An ECS cluster must exist in the account
- An existing task definition must be available
- A role must exist that trusts ecs-tasks.amazonaws.com

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `ROLE_ARN` | yes | — | Target IAM role ARN to pass as taskRoleArn override (must trust ecs-tasks.amazonaws.com) |
| `CLUSTER_NAME` | yes | — | ECS cluster name or ARN where the container instance is registered |
| `TASK_DEFINITION` | yes | — | Existing ECS task definition family or ARN to exploit via --overrides |
| `CONTAINER_INSTANCE_ARN` | yes | — | ARN of the container instance registered to the cluster (from ecs:RegisterContainerInstance) |
| `CONTAINER_NAME` | yes | — | Name of the container in the existing task definition to override |
| `PAYLOAD` | yes | — | Payload type (backdoor/attach-policy) |
| `REGION` | no | `us-east-1` | AWS region for ECS operations |

## Compatible payloads

- `backdoor/attach-policy` — Attach AdministratorAccess policy to an IAM user or role via ECS task container command
