# `iam-016` — iam:CreatePolicyVersion + sts:AssumeRole

|  |  |
|---|---|
| ID | `iam-016` |
| Category | principal-access |
| Services | iam, sts |
| Author | Seth Art |
| Aliases | `iam-createpolicyversion-assumerole`, `exploit/iam_createpolicyversion_assumerole` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-016 |

Create a new version of a customer-managed policy with admin permissions, then assume a role that has this policy attached. The new policy version takes effect immediately for all principals with that policy.

## Required permissions

- `iam:CreatePolicyVersion` — Customer-managed policy must be attached to a role the attacker can assume
- `sts:AssumeRole` — Target role must trust the attacking principal

## Additional permissions

- `iam:ListPolicyVersions` — List existing policy versions
- `iam:ListRoles` — Discover roles with the target policy attached

## Prerequisites

**Admin:**
- A customer-managed policy must be attached to a target role
- Target role's trust policy must allow your principal to assume it

**Lateral:**
- A customer-managed policy must be attached to a target role
- Target role's trust policy must allow your principal to assume it

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `POLICY_ARN` | yes | — | ARN of the customer-managed policy to create a new version of |
| `TARGET_ROLE` | yes | — | ARN of the IAM role to assume (must have the policy attached) |
| `REGION` | no | `us-east-1` | AWS region for IAM/STS operations |
| `AUTO_SWITCH` | no | `true` | Automatically switch to new identity after assuming the role |
