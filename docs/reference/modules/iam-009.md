# `iam-009` — iam:AttachRolePolicy

|  |  |
|---|---|
| ID | `iam-009` |
| Category | self-escalation |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-attachrolepolicy`, `exploit/iam_attachrolepolicy` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-009 |

A principal with iam:AttachRolePolicy can attach managed policies to any role they have this permission on. This is frequently exploited for self-escalation by attaching the AdministratorAccess managed policy to the caller's own role.

## Required permissions

- `iam:AttachRolePolicy` — Target role must be in Resource section; for self-escalation, must have permission on own role

## Additional permissions

- `iam:ListAttachedRolePolicies` — View managed policies attached to the role
- `sts:AssumeRole` — Required when starting as a user to assume the target role

## Prerequisites

**Admin:**
- Role must have iam:AttachRolePolicy permission on itself
- If starting as a user, must be able to assume the target role

**Lateral:**
- Role must have iam:AttachRolePolicy permission on itself
- If starting as a user, must be able to assume the target role

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `ROLE_ARN` | no | — | ARN of the role to escalate (auto-detected from caller if caller is a role; required when caller is a user) |
| `ADMIN_POLICY_ARN` | no | `arn:aws:iam::aws:policy/AdministratorAccess` | ARN of the managed admin policy to attach (defaults to AdministratorAccess) |
| `REGION` | no | `us-east-1` | AWS region for IAM operations |
| `VERIFY` | no | `true` | Verify escalation by calling iam:ListUsers after (true/false). Only applies when caller is already a role. |
| `AUTO_SWITCH` | no | `true` | Automatically switch to new identity after assuming role (true/false) |
