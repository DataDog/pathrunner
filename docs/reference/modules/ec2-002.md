# `ec2-002` — ec2:ModifyInstanceAttribute + ec2:StopInstances + ec2:StartInstances

|  |  |
|---|---|
| ID | `ec2-002` |
| Category | existing-passrole |
| Services | iam, ec2 |
| Author | Seth Art |
| Aliases | `ec2-modifyinstanceattribute`, `exploit/ec2_modifyinstanceattribute` |
| pathfinding.cloud | https://pathfinding.cloud/paths/ec2-002 |

Inject a malicious cloud-init script into an existing EC2 instance's userData to execute code under the instance's attached IAM role. The instance must be stopped before the attribute can be modified; the malicious script runs on the next boot. Uses the cloud-init multipart MIME format with cloud_final_modules to force execution on every subsequent boot rather than only the first.

## Required permissions

- `ec2:ModifyInstanceAttribute` — Must target the specific EC2 instance
- `ec2:StopInstances` — Must target the specific EC2 instance
- `ec2:StartInstances` — Must target the specific EC2 instance

## Additional permissions

- `ec2:DescribeInstances` — Discover target instances and verify state
- `ec2:DescribeInstanceAttribute` — Read and backup original userData before modification

## Prerequisites

**Admin:**
- EC2 instance must have an instance profile attached to a role with administrative permissions

**Lateral:**
- EC2 instance must have an instance profile attached to an IAM role

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `INSTANCE_ID` | yes | — | Target EC2 instance ID (e.g. i-0abc1234567890def) |
| `PAYLOAD` | yes | — | Payload type (backdoor/attach-policy, exfil/https, revshell/tls, exfil/s3) |
| `REGION` | no | `us-east-1` | AWS region where the target instance resides |
| `WAIT_SECONDS` | no | `30` | Seconds to wait after instance starts for cloud-init to execute |
| `CLEANUP` | no | `true` | Restore original userData and restart instance after execution (stop→restore→start cycle) |

## Compatible payloads

- `backdoor/attach-policy` — Attach AdministratorAccess policy to an IAM user or role via EC2 user-data
- `backdoor/create-access-key` — Create access keys for an existing IAM user via EC2 user-data
- `backdoor/create-role` — Create an IAM role with administrator privileges and custom trust policy via EC2 user-data
- `backdoor/create-user` — Create an IAM user with administrator privileges and optional console/programmatic access via EC2 user-data
- `backdoor/update-role-trust` — Append a trust policy statement to an existing IAM role via EC2 user-data
- `exfil/https` — Exfiltrate instance role credentials to an attacker-controlled HTTPS endpoint via EC2 user-data
- `exfil/s3` — Exfiltrate EC2 instance role credentials to an attacker-controlled S3 bucket via user-data
- `revshell/tls` — Establish a TLS-encrypted reverse shell via EC2 user-data
