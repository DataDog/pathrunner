# `iam-012` — iam:UpdateAssumeRolePolicy

|  |  |
|---|---|
| ID | `iam-012` |
| Category | principal-access |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-updateassumerolepolicy`, `exploit/iam_updateassumerolepolicy` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-012 |

Anyone with iam:UpdateAssumeRolePolicy can modify the trust policy of any role they have this permission on. This is often abused to modify a privileged role's trust policy to allow the attacker to assume it, even without sts:AssumeRole permission.

## Required permissions

- `iam:UpdateAssumeRolePolicy` — Target role must be in Resource section

## Additional permissions

- `iam:ListRoles` — Discover target roles
- `iam:GetRole` — View role trust policies

## Prerequisites

**Admin:**
- Target role must have administrative permissions

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `TARGET_ROLE` | yes | — | Name of the IAM role to modify trust policy for |
| `TRUST_PRINCIPAL` | no | — | Principal to trust (role/user ARN, account root ARN, service name). Defaults to current caller |
| `ASSUME_ROLE` | no | `true` | Attempt to assume the target role after updating trust policy |
| `REGION` | no | `us-east-1` | AWS region for IAM/STS operations |
| `AUTO_SWITCH` | no | `true` | Automatically switch to new identity after assuming the role |
