# `iam-010` — iam:AttachGroupPolicy

|  |  |
|---|---|
| ID | `iam-010` |
| Category | self-escalation |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-attachgrouppolicy`, `exploit/iam_attachgrouppolicy` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-010 |

A principal with iam:AttachGroupPolicy can attach managed policies to any group they have this permission on. This is frequently exploited by attaching an admin policy to a group the caller is a member of.

## Required permissions

- `iam:AttachGroupPolicy` — Target group must be in Resource section; for self-escalation, must be a member of that group

## Prerequisites

**Admin:**
- Principal must be a user (not a role)
- Principal must be a member of the target group
- A managed IAM policy with elevated privileges must exist in the account

**Lateral:**
- Principal must be a user (not a role)
- Principal must be a member of the target group

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `GROUP_NAME` | yes | — | IAM group name to attach the policy to (must be a group the caller belongs to) |
| `POLICY_ARN` | no | `arn:aws:iam::aws:policy/AdministratorAccess` | ARN of the managed policy to attach (defaults to AdministratorAccess) |
| `REGION` | no | `us-east-1` | AWS region for IAM operations |
| `VERIFY` | no | `true` | Verify escalation by calling iam:ListUsers after (true/false) |
