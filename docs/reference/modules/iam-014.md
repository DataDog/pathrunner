# `iam-014` — iam:AttachRolePolicy + sts:AssumeRole

|  |  |
|---|---|
| ID | `iam-014` |
| Category | principal-access |
| Services | iam |
| Author | Seth Art |
| Aliases | `iam-attachrolepolicy-assumerole`, `exploit/iam_attachrolepolicy_assumerole` |
| pathfinding.cloud | https://pathfinding.cloud/paths/iam-014 |

Attach an administrative managed policy to a target role, then assume that role to gain the elevated privileges. Requires both iam:AttachRolePolicy on the target role and sts:AssumeRole permission, with the role's trust policy allowing assumption.

## Required permissions

- `iam:AttachRolePolicy` — Must have access to attach policies to the target role
- `sts:AssumeRole` — Must have permission to assume the target role

## Additional permissions

- `iam:ListRoles` — Discover available roles
- `iam:GetRole` — View role trust policies

## Prerequisites

**Admin:**
- Target role's trust policy must allow your principal to assume it
- An AWS-managed or customer-managed policy with admin permissions must exist

**Lateral:**
- Target role's trust policy must allow your principal to assume it

## Options

| Name | Required | Default | Description |
|------|----------|---------|-------------|
| `TARGET_ROLE` | yes | — | ARN of the IAM role to escalate and assume |
| `POLICY_ARN` | no | `arn:aws:iam::aws:policy/AdministratorAccess` | ARN of the managed policy to attach (defaults to AdministratorAccess) |
| `REGION` | no | `us-east-1` | AWS region for IAM/STS operations |
| `AUTO_SWITCH` | no | `true` | Automatically switch to new identity after assuming the role |
